# 决策卡贡献与改编规则

新增内容先回答一个具体问题，再补政策、任务、付款方、能力和验证动作。欢迎提交行业版、地区版或英文解释，也欢迎指出现有卡片不适用的条件。

## 一张卡至少包含什么

- 真实输入或明确标注的构造情境，避免让读者把演示看成客户案例。
- 官方事实的文件名、文种、成文或发布日期、地区、章节或条款、原始链接。
- 项目推导单列：候选客户、付款方、可交付任务、能力和投入。
- 尚缺证据、一个小实验、继续条件、停止或调整条件。
- 内容核验日期；政策修订时记录旧判断和修改理由。

## 怎样提交

在仓库提交 issue 或 pull request，指出卡片编号和具体改动。纠错请附可打开的原始来源；市场观察注明采集方式、日期和样本范围。不提交客户原始资料、联系方式、证件、学员名单或授权不明的附件。

结构化内容统一维护在 [cards.json](cards.json)，Markdown 和网页由 `python3 scripts/build_reader.py` 从仓库根目录生成。不要分别修改三份内容。

## 发布检查

先更新固定文件白名单，再执行证据、链接和公开内容检查。生成PDF与分享图应写到仓库外，核对内容、元数据、链接和SHA-256后作为Release附件发布。

商业需求不能因被多个改编者转载而升级为事实。未验证的供应商资格、补贴对象和付款条件保留为未知。其他作者的改编仅列入衍生目录，不代表本项目背书。
